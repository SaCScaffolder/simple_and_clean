# doctor-go

A fast-path validator for services generated by [servicectl](../servicectl).
Single static binary, Go stdlib only, structured JSON output, CI-gate exit
codes.

> **Scope.** `doctor-go` is NOT a replacement for `servicectl doctor`. The
> Python doctor is the source of truth with the full check surface.
> `doctor-go` is a focused, fast subset suitable for pre-commit hooks or
> tight CI gates where you want sub-millisecond cold start.

## Why does this exist?

`servicectl` is a polyglot platform tool by design. The core CLI is Python;
the templates emit Go, Node, .NET, and Python services; and the platform
stack should reflect that reality. `doctor-go` is the Go counterpart to
`servicectl doctor` — a small, real Go program that proves the platform
team's tooling is multi-language by design, not by accident.

It also doubles as a fast validator for use cases where spinning up Python
is overkill:

- **Pre-commit hooks** — run `doctor-go ./` in 5ms vs. 200ms+ for Python
- **Tight CI gates** — fails the build before any slow job runs
- **Editor integrations** — Language Server Protocol servers can shell out
  to a fast binary

## Install

```bash
go install github.com/henryorsborn/simple_and_clean/src/doctor-go@latest
```

Or build from source:

```bash
cd src/doctor-go
go build -o doctor-go .
./doctor-go --version
```

## Usage

```bash
# Validate current directory, human-readable
doctor-go

# Validate a specific service
doctor-go --path ./my-service

# JSON output for piping into jq or CI
doctor-go --path ./my-service --json

# Treat warnings as errors
doctor-go --path ./my-service --strict
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | All checks passed |
| `1` | Warnings only |
| `2` | Errors (or warnings under `--strict`) |

## Checks performed

| Check | Severity | What it catches |
|---|---|---|
| `file:<name>` | error | Missing required files (Dockerfile, .gitignore, .gitleaks.toml, .env.example, README.md) |
| `dockerfile:multi-stage` | warn | Single-stage Dockerfile (bigger image, larger attack surface) |
| `ci:workflow` | error | No `.github/workflows/ci.yml` or `azure-pipelines.yml` |
| `secrets:env-file` | error/info | Plaintext secrets in `.env` (coarse check; gitleaks in CI is the real defense) |
| Azure overlay files | error | Missing `infra/main.bicep` or `infra/{dev,staging,prod}.bicepparam` when deploy target is azure |

The Python `servicectl doctor` has additional checks (coverage threshold
detection, advanced Dockerfile linting, etc.). Use it for the full surface.

## CI integration

```yaml
# GitHub Actions
- name: doctor-go gate
  run: |
    go install github.com/henryorsborn/simple_and_clean/src/doctor-go@latest
    doctor-go --path ./my-service --strict
```

```bash
go vet ./...       # static checks

```

The test suite uses table-driven tests against `t.TempDir()` fixtures — no
network, no external services, runs in under 100ms.
